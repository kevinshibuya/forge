# R11. X, from primary sources

Research note for the forge v2 brief (research contract R11). Evidence gathered by a scout on
2026-09-24 from docs.x.com; verdict and reading by the main session (fable). The X docs pages show no
dates.

## Verdict

X works on prepaid pay-per-use credits with no approval gate beyond a developer account. The prior fact
sheet's $0.001 "owned read" rate does not apply to connected users: reads of a connected user's posts
cost $0.005 each, which makes a naive daily metrics pull for 20 users about $90 a month and a decaying
schedule about $12. Publishing costs $0.015 per post segment, $0.20 if the segment carries a URL. The
Developer Policy requires showing the user "exactly what will be published" and getting express consent,
which forge's approve step already is.

## Evidence

1. Credits only, bought upfront in the Developer Console; a per-cycle spend cap; a resource requested
   twice in one 24h UTC window is charged once [vendor].
   [https://docs.x.com/x-api/getting-started/pricing, fetched 2026-09-24]
2. Prices: post create $0.015; post create with URL $0.200; "summoned" create $0.010; post read $0.005
   per resource; user read $0.010; media metadata $0.005; like, mute, block reads $0.001. No free tier;
   no Basic or Pro. [same]
3. The $0.001 owned-read rate applies only when "the authenticated user owns the developer app"; not
   to OAuth tokens for other users. [same; the scout flags this line as read by WebFetch and worth a
   human eye]
4. Rate limits: POST /2/tweets 100 per 15 min per user, 10,000 per 24h per app; media upload 500 per
   15 min per user; GET /2/users/:id/tweets 900 per 15 min per user; GET /2/tweets 5,000 per 15 min per
   user. [https://docs.x.com/x-api/fundamentals/rate-limits]
5. OAuth 2.0 scopes: tweet.read, tweet.write, users.read, media.write, offline.access; access tokens
   2h; refresh token only with offline.access.
   [https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code]
6. POST /2/tweets needs users.read, tweet.write, tweet.read; replies via `reply.in_reply_to_tweet_id`;
   `media.media_ids` up to 4 photos; no thread-specific limit, each segment a billed create.
   [https://docs.x.com/x-api/posts/create-post]
7. Media: simple upload POST /2/media/upload (`media_category=tweet_image`) returns `media_key`;
   chunked upload for large files; images up to 5 MB (JPG, PNG, GIF, WEBP).
   [https://docs.x.com/x-api/media/upload-media; https://docs.x.com/x-api/media/introduction]
8. Metrics: `non_public_metrics`, `organic_metrics`, `promoted_metrics` need user-context auth on the
   user's own posts and are "only available for posts created within the last 30 days"; impressions sit
   in `public_metrics` and are readable with a Bearer token. [https://docs.x.com/x-api/fundamentals/metrics]
9. User Posts timeline returns up to the 3,200 most recent posts, paginated, replies and retweets
   excludable; needs an "approved developer account" and a Project/App.
   [https://docs.x.com/x-api/posts/timelines/introduction]
10. Developer Policy: show "exactly what will be published" and get express informed consent before
    acting for a user; "never post identical or substantially similar content across multiple
    accounts"; automated replies need consent and bot bios; stored X content kept current within 24h
    and removed within 24h of a removal request. [https://docs.x.com/developer-terms/policy]
11. Automation rules page returned 403; search snippets say it bans duplicative or substantially
    similar posts, including scheduled posts across many accounts that authorised one app [secondary].
12. ToS effective 2026-01-15 defines AI prompts and outputs as user "content" the user is responsible
    for [secondary]; AI reply bots reportedly need written approval [secondary]; scheduling original
    AI-assisted posts widely reported as allowed [secondary].

## Arithmetic (mine, from items 2-3)

- Daily pull, 20 users × 30 posts × 30 days: 18,000 reads, about $90 a month.
- Decaying pull (days 1, 2, 3, 7, 14, 30): 6 reads per post; 20 users × 20 posts a month × 6 = 2,400
  reads, about $12 a month. This is the schedule R10's LinkedIn caps also want.
- Onboarding import: up to 3,200 posts × $0.005 = $16 per user at the cap; about $0.50 at 100 posts.
  Import depth becomes a setting with a cost shown.
- Publishing: a 5-segment thread $0.075; $1.00 if every segment carries a URL. Links belong in one
  segment, or in the profile, not in every segment.

## Reading

X is the platform where the brief's decision 22 holds as written: connect, import history through the
timeline API within minutes, run the Voice profile. It is also where decision 18 ("Publish never posts
the same body twice to one Platform") has a policy behind it, and where Adapt has to change more than
the format when a Tenant later has two Voices on X. Item 10's consent rule maps onto the approve step
if the Workspace shows the exact platform rendering of the body before approval, which is a UI
requirement for S4 to carry, not a new act. Refresh tokens every 2h means the Publish worker refreshes
before every call; a Tenant who revokes access breaks the next refresh, and the Armed post falls back
to a reminder, which decision 16 already says.

## Decision fed

- X publish path: OAuth 2.0 PKCE with the five scopes; refresh before each call; threads by reply
  chaining; media via simple upload; the Workspace shows the platform rendering before approve.
- Outcomes cadence (decision 17): the decaying schedule; `non_public_metrics` only inside 30 days,
  `public_metrics` after.
- Onboarding import (decision 22): timeline API, depth as a setting with the cost shown; the archive
  upload as fallback.
- Budget (decision 5): X API costs are metered per Tenant alongside model costs.

## Open items

- The automation rules page needs a browser read; AI-content labelling rules unverified from primary.
- Media upload price (only media metadata at $0.005 was found); whether `non_public_metrics` reads are
  billed per post like other reads; whether $0.20 applies to any URL or only external links.
- "Approved developer account" wording versus self-serve signup under pay-per-use.
- X data archive format (`data/tweets.js`) not verified.

## Confidence

High on prices, scopes, token lifetime, rate limits, media limits, the 30-day window (primary). Medium
on the owned-read exclusion (read by tool, worth a human eye). Low on automation and AI-content rules.
